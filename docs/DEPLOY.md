# Publish Aquire

The game has one React/Vite codebase. Capacitor packages the production `dist/` files for iOS and Android. The connected Supabase project already hosts Auth, the private database, the daily cleanup job, and the authoritative `acquire-room` Edge Function; it does **not** serve the web frontend. Supabase [says custom domains for Edge Functions are not intended for hosting frontend apps](https://supabase.com/docs/guides/platform/custom-domains). Put `dist/` on a static HTTPS host such as Cloudflare Pages or Netlify, using `npm run build` and `dist` as the output directory.

The connected project’s public URL and publishable key are checked in at `src/lib/supabase-public.json`. Cloudflare’s GitHub-triggered builds therefore enable online play without a local `.env` file. Push the updated app to the branch Cloudflare builds, then refresh the published site. For a different Supabase project, before a web build set `VITE_SUPABASE_URL` to the project **base URL** (`https://…supabase.co` with no `/functions/...` suffix) and `VITE_SUPABASE_PUBLISHABLE_KEY` to the public key in the build host. Never put a service key in a `VITE_` variable. The hosting provider must serve `/index.html` for the root route; this app currently uses no deep client routes. Run `npm run preview` to inspect the same production output locally. When code or environment changes, rebuild the website and run `npm run cap:sync` before rebuilding native packages.

The backend is reproducible with `npx supabase db push` followed by `npm run supabase:sync && npx supabase functions deploy acquire-room`. Enable Anonymous Sign-Ins in Supabase Auth. The migrations create the private room service, 2008 edition boundary, compact history, daily retention, expanded maps, room ending, and receive-only Realtime authorization. Deploy every migration and the updated Edge Function before publishing a client with the newest maps. No web hosting or store credentials are stored in this repo.

For TestFlight/App Store Connect, open `ios/App/App.xcodeproj` in Xcode 26+, assign the owner’s Apple Developer team and signing identity, set the final bundle ID/version, then Archive and distribute through App Store Connect. The project compiles and runs in the iOS 26.1 simulator; its current simulator `.app` is not a distributable App Store package. [Apple’s current SDK requirement](https://developer.apple.com/news/upcoming-requirements/?id=02032026a) is met by Xcode 26.

For Google Play, supply a private release keystore/signing configuration, increment `versionCode`, run `./gradlew bundleRelease`, and upload the signed `.aab` in Play Console. The included debug APK is for testing. The app targets API 36, matching [Google Play’s current requirement](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en).

Store publication also needs the owner’s developer accounts, screenshots, support contact, public privacy-policy URL, data-safety/app-privacy declarations, and review of the rights to use the **Acquire** name, chain names, and edition references. [Apple](https://developer.apple.com/app-store/review/guidelines/uk/) and [Google Play](https://support.google.com/googleplay/android-developer/answer/9888072?hl=en) both require rights to third-party material. We cannot certify those rights or guarantee store approval from a technical build.
